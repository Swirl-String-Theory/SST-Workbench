# SST Knot Library integration — v0.3.0

## Contract

Scientific atlas runs require the exact pinned dependency `sst-knot-library/0.2.5`.
The dependency is not vendored and is not installed silently. The run resolves it from
`SST_KNOT_LIBRARY_HOME` or the repository-relative configured path, then verifies:

- `RELEASE.json` version identity;
- the full `MANIFEST_SHA256.txt`;
- the pinned offline KAtlas snapshot hash;
- the source-catalog hash;
- runtime version and imported module root.

The resulting dependency attestation is frozen in the atlas preregistration and in the
run evidence. Any later dependency-byte change blocks scoring.

## KnotRecord boundary

The historical parent geometries (Fremlin `.short`, Gilbert/SONO Fourier) are loaded by
SST Knot Library. The constructive braid parent is generated by its pinned KAtlas braid
reference. Every *generated test realization* is then written to disk and immediately
reloaded through `make_knot_record(expected_topology="3_1")`.

The portable KnotRecord hash binds:

- actual test geometry bytes/canonical geometry;
- component count;
- expected `3_1` topology;
- KAtlas snapshot identity;
- source-format/source-provider metadata;
- SST Knot Library version.

The downstream candidate stage recomputes that KnotRecord and rejects any mismatch.

## Topology semantics

A KAtlas reference is not geometry certification. In v0.3.0, scientific screening accepts
only sources that have both:

1. a pinned KAtlas `3_1` reference through SST Knot Library; and
2. the independent numerical three-crossing trefoil diagram witness at N=64,96,128.

This status is explicitly
`SUPPORTED_NUMERICAL_DIAGRAM_NOT_EXTERNAL_PROVIDER_CERTIFIED`.
Publication-oriented topology certification remains blocked until an independent geometry
provider or interval/ambient-isotopy proof is available.

## No gate relaxation

0/4 and S40-S60/Phase B therefore did not produce a trefoil Floquet/intervention certificate.
v0.3.0 changes provenance/input admission only. S37 remains frozen at 0.035 for BASIC and
