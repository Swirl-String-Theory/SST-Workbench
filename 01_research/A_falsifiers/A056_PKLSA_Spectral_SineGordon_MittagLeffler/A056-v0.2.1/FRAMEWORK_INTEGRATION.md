# A056 v0.2.1 integration with SST Falsifier Framework v1.0.2-dev

A056 v0.2.1 is the first consumer updated from the earlier `1.0.0.dev0` snapshot to the recovered **SST Falsifier Framework v1.0.2 development contract**.

The vendored package is labeled `1.0.2.dev0` because the canonical framework is still under construction.  A056 does not claim that this vendored snapshot is the final canonical v1.0.2 source tree.

## Authority boundary

The DD32 lane is a high-precision **screening** backend.  A DD32 scalar is represented as

\[
x \approx x_{\mathrm{hi}}+x_{\mathrm{lo}},\qquad x_{\mathrm{hi}},x_{\mathrm{lo}}\in\mathrm{binary32}.
\]

It does not have the exponent range or exact semantics of IEEE binary64.  A056 therefore does not allow DD32 to replace CPU/Python or C++ FP64 certification for a final scientific gate.

## Gate-5 safety backport

The synthetic A056 v0.2.0 smoke exposed a framework bug: different synthetic `source_group` labels generated by one control generator could be counted as physical cross-source replication.

A056 v0.2.1 locally backports the proposed v1.0.3 fix:

- `evidence_class` is mandatory and one of `synthetic_control`, `simulation`, `independent_source`, `experimental`;
- synthetic controls are grouped by `generator_id` / `solver_id`, not by arbitrary per-case labels;
- simulations are grouped conservatively by solver-independence group / solver ID;
- only `independent_source` and `experimental` contribute to `G5_CROSS_SOURCE_REPLICATION`;
- synthetic recovery is reported separately as `G5_CONTROL_REPLICATION`;
- `G6_MECHANISM_PHYSICS` cannot PASS without physical cross-source replication.

The same change is shipped separately as an upstream-ready v1.0.2 -> v1.0.3 Gate-5 patch.
