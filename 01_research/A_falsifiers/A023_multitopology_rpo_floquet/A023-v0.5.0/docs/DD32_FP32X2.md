# Experimental DD32 / FP32x2 SYCL backend

## Purpose

Intel Arc A770 does not expose native IEEE binary64.  v0.4.6 therefore adds an **experimental double-single** backend in which every device scalar is represented as

\[
x \approx x_{\mathrm{hi}} + x_{\mathrm{lo}},\qquad x_{\mathrm{hi}},x_{\mathrm{lo}}\in \mathrm{binary32}.
\]

This is called `DD32`, `FP32x2`, or double-single arithmetic.  It is **not IEEE FP64**: exponent range remains that of binary32 and the ideal significand capacity is about 48 binary bits rather than binary64's 53 bits.  Actual accuracy is measured, never assumed.

## Error-free transforms

The worker uses compensated transforms.  Addition uses a Knuth/Dekker-style `TwoSum`.  Multiplication starts with

\[
p=\operatorname{fl}_{32}(ab),\qquad e=\operatorname{fma}(a,b,-p),
\]

so `p+e` recovers the product residual when the device FMA obeys the expected IEEE fused semantics.  DD multiplication includes both cross terms and the low-low term.  Division uses three quotient corrections.  Square root uses a binary32 `sqrt` seed followed by two DD Newton corrections,

\[
y_{k+1}=y_k+\frac{x-y_k^2}{2y_k}.
\]

The Biot--Savart kernel evaluates coordinates, segment midpoints, squared radius, regularized denominator, cross products, scaling, and the segment accumulation in DD32.

## Transport

Input coordinates remain binary64 over the Python-to-worker pipe.  The worker host splits each scalar as

\[
x_{\rm hi}=\operatorname{float}(x),\qquad
x_{\rm lo}=\operatorname{float}(x-x_{\rm hi}),
\]

before sending float-only buffers to the device.  This avoids destroying the low component before GPU execution.  Device output is stored as `(hi,lo)` and combined on the worker host into a Python/NumPy binary64 result.

## Compiler guardrail

The worker is built with

```text
-fsycl -fsycl-device-code-split=per_kernel -O3 -fp-model=precise
```

because error-free transforms must not be invalidated by fast-math reassociation.  Explicit `sycl::fma` is used for the product residual.

## Validation gates

Run:

```bat
run_sycl_dd32_smoke.cmd
```

The smoke compares ordinary Arc FP32 and DD32 against the Python FP64 midpoint-Biot--Savart reference on three velocity cases and one finite-difference directional-Jacobian stress case.  Initial experimental acceptance criteria are:

\[
\max \varepsilon_{v,\mathrm{DD32}}\le 10^{-8},
\]

\[
\varepsilon_{Jd,\mathrm{DD32}}\le 2\times10^{-6},
\]

and at least a 20x error reduction relative to ordinary FP32 on every smoke case.

These thresholds validate the *numerical backend*, not SST physics.  CPU/OpenMP FP64 remains the reference for confirmatory scientific claims until campaign-level parity is demonstrated.

## Campaign commands

After the strict smoke passes:

run_archive_extra_extended_sycl_dd32.cmd

## References

- T. J. Dekker, *A floating-point technique for extending the available precision*, Numerische Mathematik **18**, 224--242 (1971), DOI 10.1007/BF01397083.
- G. Da Graça and D. Defour, *Implementation of float-float operators on graphics hardware*, arXiv:cs/0603115 (2006).  The paper demonstrates emulated extended precision from pairs of single-precision values on GPU hardware.
- Intel oneAPI documentation, *Accuracy Versus Performance Tradeoffs in Floating-Point Computations*: higher optimization levels can enable fast floating-point transformations; the DD worker therefore requests precise FP semantics.
