# DD32 / FP32x2 SYCL precision lane

## Status

`sycl-dd32` is an experimental high-precision GPU lane for devices such as Intel Arc A770 that do not expose native IEEE binary64. It is **not IEEE FP64** and it is not an IEEE-defined `FP48` format.

Each device scalar is represented as

\[
x \approx x_{\mathrm{hi}} + x_{\mathrm{lo}},\qquad x_{\mathrm{hi}},x_{\mathrm{lo}}\in \mathrm{binary32}.
\]

The preferred names are **DD32**, **FP32x2**, or **double-single**. The pair has binary32 exponent range and a nominal significand capacity around 48 bits; effective accuracy must be measured, not inferred from that nominal count.

## Arithmetic

The worker implements:

- Knuth/Dekker-style `TwoSum` compensation for addition;
- product residual from explicit FMA, \(e=\operatorname{fma}(a,b,-\operatorname{fl}_{32}(ab))\);
- cross terms and low-low term in DD multiplication;
- three quotient corrections for division;
- binary32 square-root seed followed by two DD Newton corrections;
- DD32 accumulation through the regularized midpoint Biot--Savart kernel.

The regularized kernel remains

\[
\mathbf v(\mathbf x)=\frac{\Gamma}{4\pi}\sum_s
\frac{\Delta\boldsymbol\ell_s\times(\mathbf x-\mathbf m_s)}
{\left(\|\mathbf x-\mathbf m_s\|^2+a^2\right)^{3/2}}.
\]

Coordinates are transported from Python to the worker as binary64. The worker host splits each coordinate as

\[
x_{\rm hi}=\operatorname{float}(x),\qquad
x_{\rm lo}=\operatorname{float}(x-x_{\rm hi}),
\]

then sends float-only `(hi,lo)` data to the device. Results return as `(hi,lo)` and are recombined in host binary64 for transport to NumPy.

## Compiler contract

DD32 depends on error-free transforms, so the SYCL worker is built with

```text
-fsycl -fsycl-device-code-split=per_kernel -O3 -std=c++17 -fp-model=precise
```

and uses explicit `sycl::fma` for the product residual. Fast-math/reassociation is not allowed for this lane.

## Validation gates

The v1.0.6 backend selftest requires:

\[
\max \epsilon_{v,\mathrm{DD32}}\le 10^{-8},
\]

\[
\epsilon_{Jd,\mathrm{DD32}}\le 2\times10^{-6},
\]

and

\[
\frac{\epsilon_{\mathrm{FP32}}}{\max(\epsilon_{\mathrm{DD32}},\epsilon_{\rm floor})}\ge 20
\]

for every DD32 velocity smoke scenario and the deterministic directional finite-difference stress test.

These gates certify the numerical lane only. Python/C++ FP64 remain the reference/certification lanes for scientific claims unless a specific future campaign preregisters and validates a stronger DD32 authority rule.

## Historical SST provenance

This precision lane restores the method used in the earlier SST v0.4.6/v0.4.8 GPU work. The historical smoke reported velocity errors of order \(2\times10^{-13}\), a directional-Jacobian error of order \(10^{-9}\), and more than \(10^7\) improvement over ordinary FP32 in that test set. v1.0.6 does not assume those numbers will reproduce: it reruns parity on the current compiler, driver, worker source, and device and stores the new results in `build/BACKEND_SELFTEST.json`.

## Windows oneAPI 2026 linker note (v1.0.6)

`-fp-model=precise` can make the Windows host link depend on Intel's dynamic compiler math library `libmmd.lib`.  Merely finding `icpx.exe` or calling `setvars.bat` is not treated as sufficient evidence that the linker search path is complete.  The v1.0.6 builder verifies the effective `LIB`; when `libmmd.lib` is absent, it searches the active compiler-local `lib` tree, prepends the resolved directory to `LIB`, and records `libmmd_path` in build provenance.
