# v0.1.1 native-build fix

The v0.1.0 Windows/MSVC build failed because the C++ extension used the POSIX/global type `ssize_t`.
MSVC does not define that name in this context. The first real compiler failure therefore occurred at
`const ssize_t N = ...`; the remaining diagnostics were parser cascades.

v0.1.1 changes:

- uses `py::ssize_t` through the local alias `index_t`;
- uses explicit `py::array::ShapeContainer` construction for pybind11 3.x compatibility;
- adds `<stdexcept>` explicitly;
- makes `SST_BACKEND=native` strict: a missing extension is now a hard failure instead of silently falling back to Python;
- adds native-vs-reference parity tests;
- declares NumPy and pybind11 in `pyproject.toml` build requirements;
- aligns package/catalog metadata with A046 and bumps the patch version to v0.1.1.

The blind mathematical formulas and preregistered tolerances are unchanged.


This fix is inherited unchanged by v0.2.0.
