# v1.0.9 maintenance consolidation (2026-10-17)

**Source:** verified v1.0.8 `LOCAL_VALIDATED_CANDIDATE`, extracted from the A062-v0.7.0 Workbench distribution (source manifest: 99/99 byte SHA-256 matches). Historical v1.0.7 `CANONICAL_FROZEN` records remain unchanged.

## Retention policy preserved from v1.0.8

Every BASIC/FULL/CERTIFY run gets a new `RUN_ID.json`. The previous working output directory is **renamed** to a unique archival location, not deleted. ZIP and PDF publication is exclusive-create and phase-aware, with separate BLIND/REVEALED names and one shared run ID. Existing legacy artifacts remain intact. An instance-scoped lock rejects concurrent publishers. The canonical scientific output working path remains unchanged for pipeline compatibility.

## Output manifest PDF circularity fixed

`SCIENCE_EVIDENCE_MANIFEST.json` is created **once**, immediately after scientific run artifacts and before generating `AUTO_RESULTS.tex` and publishing any PDF. Its SHA-256 commits to the blind scientific output inventory; it excludes only derivative report/manifest/reveal artifacts. The automatically generated TeX and resulting PDF display this science-evidence digest, **not** the evolving `OUTPUT_MANIFEST` digest.

`OUTPUT_MANIFEST.json` is still finalized and verified after PDF publication, before publishing a ZIP. Reveal and REPORT_ONLY reject changes to science evidence. These are separate immutable identifiers with different scope; never present them as interchangeable.

## Portable protocol hash is diagnostic, not a replacement

`FROZEN_PROTOCOL.json` includes `portable_bundle_sha256`, computed over strictly UTF-8 normalized text with CRLF/CR mapped to LF and normalized POSIX-relative names. The original raw byte-exact `bundle_sha256` and per-file SHA-256 checks are unchanged and remain authoritative for protocol freeze and reveal gating. The portable digest can explain Windows/Linux newline-only differences; it **cannot** authorize reveal when frozen raw bytes differ, or deem modified science equivalent. Binary and encoded documents outside the registered text-only protocol set are not eligible for this diagnostic.

## PDF table and rerender

Generated gate ledgers use bounded columns, breakpoints for compound IDs/statuses, and explicit status font scaling; backend/source JSON is display-wrapped. The generated table needs no extra TeX packages beyond `booktabs,longtable`. LaTeX engine can be explicitly selected using `SST_LATEX_ENGINE` or `report.pdf_engine` (latexmk, pdflatex, xelatex, lualatex). No TeX engine means normal report creation can skip PDF unless configured strict. `run_all.cmd REPORT_ONLY` on a generated **instance** publishes a unique `..._RERENDER_..._FALSIFIER_REPORT.pdf` + `.render.json` sidecar outside the audited output tree without changing its run ID, hashes, ZIP, or existing PDF. Report-only requires valid science evidence and a valid final output manifest.

## Scientific nonchanges

No changes to gates, thresholds, source admissibility, C++/SYCL workers, arithmetic, DD32 transport, precision policy, or target-bearing preregistration semantics. Historical instances retain their original framework pin. The Arc A770 DD32 hardware JSON carried forward from earlier releases is historical evidence of byte-identical kernels, **not a newly performed Windows v1.0.9 certification run**.

## Deployment boundary

This release is source/test `CANONICAL_FROZEN`. For production certification on the Windows/Intel Arc A770 target, run `run_all.cmd ALL` and retain `BACKEND_SELFTEST.json` / `DD32_PARITY_SMOKE.json`. If target parity fails, do not promote the run to certified scientific evidence. Do not edit frozen framework or existing scientific instances in place.
