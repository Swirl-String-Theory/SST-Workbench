# v1.0.6 consolidation record

v1.0.6 starts from the frozen v1.0.4 source tree and reconciles three parallel v1.0.5 hardening efforts.

## Instance bootstrap

Generated instances now share one `framework_bootstrap.py` contract for `run_instance.py` and pytest `conftest.py`:

1. `SST_FALSIFIER_FRAMEWORK_ROOT` is authoritative when explicitly set;
2. otherwise `.sst_framework_root` is authoritative when present;
3. only locator-less legacy instances may autodiscover the newest framework under the canonical nested `06_templates/SST_Falsifier_Framework/` family;
4. an invalid explicit override or locator fails closed;
5. a stale globally/editably installed `sst_falsifier` cannot override the pin.

`run_python.cmd` uses `run_python.py` to establish the same framework pin before launching instance-local modules or scripts.

## Reveal orchestration

`REVEAL_IF_ALLOWED` provides a non-throwing policy preflight for unattended orchestration. Strict `REVEAL` remains fail-closed.

Before reveal, the framework verifies:

- `GATE_LEDGER.json` self-hash;
- `RUN_SUMMARY.json` -> gate-ledger SHA-256 binding;
- exact `OUTPUT_MANIFEST.json` self-hash and current output-tree inventory;
- frozen protocol identity;
- preregistered reveal gate/status policy;
- unresolved-gate policy;
- nonced reveal/blind-term commitments during reveal execution.

A successful reveal writes `REVEAL_DECISION.json` before the final output manifest and revealed ZIP are produced, so the decision is part of the packaged provenance.

## Stale reveal cleanup

A new blind run removes old reveal-only ledgers/decisions, the `revealed/` directory, revealed ZIP, output `POST_RUN_DISCUSSION.tex`, and the previously published parent-folder report PDF. This prevents post-reveal material from surviving into a new blind run when later rendering is skipped or fails.

## Precision/backend scope

No Python reference, C++/OpenMP, SYCL FP32, DD32 arithmetic, compiler/linker, threshold or backend-authority source was changed from v1.0.4. Existing target-machine backend evidence therefore remains provenance evidence for the unchanged numerical backend implementation; v1.0.6 changes orchestration/bootstrap/integrity semantics only.
