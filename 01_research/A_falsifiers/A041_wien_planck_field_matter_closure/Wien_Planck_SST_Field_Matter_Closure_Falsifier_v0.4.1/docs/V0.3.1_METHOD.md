# v0.3.1 method correction

v0.3.1 is a scientific-certification release driven by the first blind PTSA v0.3.0 campaign. No PTSA parameter identities are required to motivate these corrections.

## Issue A — single-shot horizon extension

v0.3.0 correctly flagged first-bin FFT peaks, but extended the horizon only once. A new first-bin peak after that extension could still terminate the observation stage unresolved.

**Correction:** iterative, target-free horizon enlargement with explicit round/factor caps and a final `RESOLVED` / `UNRESOLVED_HORIZON_CAP` status.

## Issue B — full marker velocity in the RE gate

Seed qualification judged coherent rolling in the normal centerline velocity, while the later relative-equilibrium gate included tangential marker velocity. These are different notions for an unlabelled centerline.

**Correction:** split \(\epsilon_{\rm RE}^{\rm full}\) from \(\epsilon_{\rm RE}^{\perp}\). Gate on the latter; retain the former for later material-core work.

## Issue C — mesh degradation on long trajectories

A fixed small number of scheduled reparameterizations was insufficient once the frequency horizon grew.

**Correction:** adaptive arclength redistribution triggered by preregistered mesh CV/edge-ratio diagnostics. The hard gate evaluates the maximum defect observed before cleanup.

## Issue D — energy direction did not necessarily equal discovered frequency mode

v0.3.0 measured energy along a broadband normal perturbation while extracting frequency from a dynamically discovered POD mode. Therefore \(\Delta E/\omega\) could combine different degrees of freedom.

**Correction:** a dedicated broadband probe first discovers one mode. That mode is normal-projected, RMS-normalized, frozen, and subsequently used for both the symmetric energy perturbation and the dynamic frequency measurement.

## Issue E — missing-case ambiguity

A numerical exception could remove a whole amplitude block from the action table.

**Correction:** each preregistered slot emits either an `OK` row or an explicit error row. `UA0b_complete_campaign_coverage` prevents a scientific PASS on incomplete data.

## Non-changes

v0.3.1 does **not** change:

- PTSA v1.0.0 or its 48-candidate parameter grid;
- the strict \(L_{\rm hat}=\Gamma_{\rm hat}=1\) blind normalization;
- the prohibition on SST constants/SI targets before reveal;
- the regularized Biot–Savart line-energy kernel;
- the requirement for native C++ in production configs;
- the rule that a discrete frequency alone is not action quantization.
