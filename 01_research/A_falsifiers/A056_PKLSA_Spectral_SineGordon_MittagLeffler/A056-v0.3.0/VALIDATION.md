## Live E010 contract inspection

The connected E010-v0.3.1 3_1 qualification ledger was inspected while constructing this release. The strict preregistered selector `contributes_new_upstream_provider=true` currently exposes 2 upstream-provider representatives:

- `CAR_042c4a4f554aef25`: provider `knotplot`, independence `knotplot-relaxed:3_1`.
- `CAR_f0023c079d7502c1`: provider `gilbert`, independence `gilbert-ideal:3_1`.

Carrier IDs are *not* hard-coded into the provider runner; they are rediscovered from the live E010 ledger and then hidden behind opaque IDs before A056 scoring. The runtime code re-hashes original source bytes and the E010 geometry contract.

## A047 method provenance

The 3-D Euler provider is an instance-local adaptation of the audited A047-v0.3.0 E010 route. Exact source hashes used for provenance are in `A047_METHOD_PROVENANCE.md`. A056 does not import A047 at runtime and does not inherit its verdicts.

## What has not been run here

A true E010 dynamic campaign was not executed in this container because the local SST-Workbench/E010 original source-byte tree is not mounted here. The release therefore contains **no claimed real PKLSA/Euler SG/ML result**. Run one of the supplied `run_e010_*.cmd` launchers on the Workbench machine.

## Expected evidence semantics

All E010 finite-core/Euler outputs generated by v0.3.0 are labeled `evidence_class=simulation`. Two E010 upstream providers may therefore close a replicated **simulation** conclusion, but they cannot close physical G7 under framework v1.0.4. Resolution levels of the same carrier are convergence replays and are forced ineligible for replication.

## Windows provider-entry hotfix validation

The first real Workbench launch exposed a Python path issue before any E010 data were read: executing `python tools\build_e010_provider.py ...` makes Python place the `tools` directory, not the A056 instance root, at `sys.path[0]`.  The result was `ModuleNotFoundError: No module named 'a056_provider'`.

Hotfix 1 makes both entry styles valid:

```text
python -m a056_provider.campaign --help
python tools\build_e010_provider.py --help
```

The three `run_e010_*.cmd` launchers now use the module form.  A subprocess regression test also exercises the direct-script form.  This is an instance-launcher fix only; the frozen protocol bundle SHA-256 remains unchanged.
