## Before running science

1. Replace every `REPLACE_BEFORE_FREEZE` / `\SSTTODO{...}` field.
2. Make `science_contract.json` and `report/FALSIFIER_REPORT.tex` agree exactly.
3. Define source independence in `source_contract.json`.
4. Implement scientific gates in `experiment/pipeline.py`.
5. Put reveal-bearing mappings and forbidden-term lists only under `private/`. `FREEZE` creates a nonced public commitment for the private forbidden-term list.
6. Run `run_all.cmd FREEZE` once.
7. After freeze, any protocol change requires a new falsifier version.

Fresh instances are intentionally `UNVALIDATED` and cannot accidentally certify the example skeleton.
## Instance-local Python entry points

If a custom launcher executes code below a subdirectory such as `tools\`, prefer the package/module form through the generated helper:

```bat
run_python.cmd -m my_instance_package.tool --arg value
```

Direct `python tools\script.py` execution changes `sys.path[0]` to the `tools` directory. Such a script must explicitly bootstrap the instance root before importing sibling instance-local packages. This avoids Windows-only `ModuleNotFoundError` failures that occur before the scientific pipeline starts.


## v1.1.0 report-only

After a completed run, `run_all.cmd REPORT_ONLY` creates a unique rerendered PDF beside the instance; it does not change the existing output tree, source manifest, ZIP, or earlier PDF.

## v1.1.0 full diagnostic gating

To implement a gate, add an evaluator to the mapping in `experiment/pipeline.py` and keep `ledger.run_evaluators(evaluators)`. All enabled available evaluators run even after a prior `FAIL`/`UNRESOLVED`. A disabled gate is `NOT_APPLICABLE`; unimplemented gates are `UNRESOLVED` and `NOT_EXECUTED`. Never infer a scientific claim from a diagnostic-only PASS. The gates' `qualification` and `blocked_by` appear in the JSON ledger and PDF. G9 is a separate reveal phase.


## DD32 (v1.1.1 development)

New GPU instances default to `[gpu] precision = "dd32"`. Intel requires a native oneAPI SYCL worker; CUDA requires an independently compiled native CUDA DD32 worker (NVCC 12.6 on the GTX 1060). No torch.float32 substitution is allowed. This mode is **not** certified until passed on the actual GPU and must be logged as dd32-fp32x2, not FP64.
