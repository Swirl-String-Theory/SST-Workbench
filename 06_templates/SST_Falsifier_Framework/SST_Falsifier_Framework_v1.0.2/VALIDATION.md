# SST Falsifier Framework v1.0.2 — Validation Record

Validation date: 2026-10-07

## Verified in this release environment

- Python framework test suite: **28 / 28 PASS**.
- Raw `instance_template/report/FALSIFIER_REPORT.tex`: compiled successfully with `pdflatex` to a 7-page A4 document.
- A report generated by `tools/new_falsifier.py`: compiled successfully with `pdflatex` to a 7-page A4 document.
- Create-once preregistration, gate-DAG enforcement, HMAC opaque identifiers, nonced reveal commitments, blind contamination scanning and deterministic packaging remain covered by regression tests.
- Strict backend authority remains enforced: a Python fallback cannot satisfy a C++/SYCL certification or screening lane.
- C++ compiler-provenance parser regression: a representative setuptools/MSVC command is identified as the actual `cl.exe` compiler, with MSVC family/toolset and Python ABI recorded in the build metadata/fingerprint rather than an unrelated generic `c++.exe` found on `PATH`.
- DD32 CPU arithmetic regression: the double-single/FP32x2 emulation of the regularized Biot--Savart kernel agrees with the NumPy FP64 reference at relative L2 `3.5273070350357435e-15` on the deterministic validation case. This regression validates the arithmetic formulation, not Arc device execution.
- DD32 is explicitly represented as `dd32-fp32x2`, `SCREENING_ONLY`, **not IEEE FP64**, with nominal approximately 48 significand bits and binary32 exponent range.
- The backend parity harness now contains three velocity cases (circle, trefoil, near-core ring) plus a centered directional finite-difference stress test.
- DD32 gates are fixed at velocity relative-L2 <= `1e-8`, directional finite-difference relative-L2 <= `2e-6`, and >= `20x` error reduction relative to ordinary SYCL FP32.
- Canonical framework discovery is restricted to `06_templates/SST_Falsifier_Framework/SST_Falsifier_Framework_v*` (plus explicit `.sst_framework_root` / environment override); there is no `04_tools/D_proof` fallback.

## Target-machine checks still required

This release environment has no Intel Arc/oneAPI device and is not a Windows MSVC target, so the following are **not claimed as executed here for v1.0.2**:

- fresh Windows pybind11 extension compilation with the new compiler-provenance capture;
- Intel Arc A770 SYCL FP32 execution;
- Intel Arc A770 SYCL DD32/FP32x2 execution and historical-accuracy reproduction.

The user's immediately preceding v1.0.1 target-machine run established that the same host C++/OpenMP and external Arc/SYCL architecture works on the target system. v1.0.2 must nevertheless be rerun locally because the DD32 lane and compiler-provenance logic are new release-critical changes.

Recommended target-machine validation:

```bat
run_all.cmd ALL
```

or DD32 alone:

```bat
run_all.cmd DD32
```

Expected machine-readable outputs:

```text
build/BACKEND_SELFTEST.json
build/DD32_PARITY_SMOKE.json
```

A valid Windows result should report the actual compiler used by setuptools (normally Visual Studio `cl.exe` on this setup), the Intel Arc A770 device for SYCL, ordinary FP32 parity, DD32 parity, and the DD32 improvement factors.
