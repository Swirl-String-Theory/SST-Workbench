# A012 Maxwell-3 v0.3.0 — Windows native build hotfix (2026-09-29)

## Failure reproduced from user log

MSVC compiled `cpp/native.cpp`, but the linker failed with:

`LNK1104: cannot open file ...\_native.cp314-win_amd64.exp`

The generated linker path was 275 characters long. The original dynamic setuptools file embedded the C++ source as an absolute path. Setuptools then mirrored that absolute source hierarchy under `build\temp.win-amd64-cpython-314\Release\...`, duplicating most of the already-deep SST-Workbench path.

This is a build-path defect, not a missing Visual Studio component: `cl.exe` compiled `native.cpp` successfully and `link.exe` was invoked correctly.

## Fix

`src/sst_maxwell3_blind/build_ext_if_needed.py` now:

- gives `Extension(...)` the repository-relative source path `cpp/native.cpp`;
- uses short `build\t` and `build\l` directories for temporary object/import-library output;
- retains C++17 and OpenMP flags unchanged.

The `run_all_basic.cmd`, `run_all_extended.cmd`, and `run_all_certification.cmd` wrappers now also propagate install/preflight failures correctly. The old `call ... || exit /b %errorlevel%` construct could expand `%errorlevel%` before the failed command executed and therefore return exit code 0.

## Scientific invariance

No C++ numerical kernel, Python reference kernel, gate threshold, carrier-admission rule, blind commitment, PKLSA source contract, or output schema was changed.

Local pure-Python regression after the patch: `6 passed`.

Windows/MSVC compilation must still be rerun on the SST-Workbench host to certify this platform-specific fix.

## Runtime loader hotfix 2 — source-native Gilbert carriers

The first successful Windows build exposed a second, independent integration defect in the
Maxwell-3 PKLSA adapter.  Basic admission selected five valid A004/Gilbert upstream carriers,
but all five failed before M6/M7 or M1--M3 evaluation with the same redacted RuntimeError
digest.  The digest resolves to E010's generic `.gz` loader guard:

`gzip geometry requires sst_knotlib adapter; no silent format guess`

Those carriers have representation `gilbert_ab_record`: their `source_path` is the immutable
compressed Gilbert catalogue, not an XYZ geometry file.  E010's own production campaign does
not send that representation through `io_geometry.load_geometry`; it calls
`gilbert.find_gilbert_record(source_path, topology_id)` and then
`gilbert.sample_gilbert_components(..., n>=4096)`.

`pklsa_adapter.py` now mirrors that upstream E010 dispatch exactly before applying the existing
raw-byte SHA-256 and geometry SHA-256 checks.  The scientific preregistration, thresholds,
carrier ordering, blinding, C++ kernels, and output schemas are unchanged.

The already-frozen failed run must be retained as audit evidence.  Rerun BASIC normally; the
CLI creates a new timestamped output directory, so the original frozen ledger is not modified.

Regression after loader hotfix 2: `7 passed`, including a synthetic compressed
`gilbert_ab_record` that deliberately makes the generic loader raise if it is called.

## Re-entry hotfix 3 — idempotent E010 editable/native install

A successful BASIC run followed by `run_all_extended.cmd` exposed a Windows DLL-lock re-entry
failure.  The extended wrapper called `run_00_install.cmd` again, and that script unconditionally
ran `pip install -e E010-v0.3.1`.  Setuptools successfully rebuilt `pklsa_builder._native`, but
Windows refused to delete/overwrite the already-installed `_native.cp314-win_amd64.pyd` and the
run stopped with `Access is denied` before preflight or science execution.

The scientific package was already valid at that point; rebuilding the same E010 native module
was unnecessary.  Hotfix 3 makes the install stage idempotent:

- `pklsa_install_probe.py` verifies that `sst-pklsa` resolves from the selected E010-v0.3.x
  release, the installed distribution version matches, `pklsa_builder._native` imports from the
  same release, and the native binary is not older than `cpp/pklsa_native.cpp`;
- when that probe passes, `run_00_install.cmd` reuses the existing editable/native install and
  does not overwrite the `.pyd`;
- `--force-pklsa-reinstall` or `SST_PKLSA_FORCE_REBUILD=1` remains available for an intentional
  E010 rebuild;
- a failed intentional rebuild now prints the specific Windows DLL-lock remediation and preserves
  exit code 3.

No preregistration, target, carrier admission rule, numerical kernel, threshold, blind commitment,
or result schema changed.  Frozen BASIC outputs remain valid and should not be regenerated merely
because of this orchestration fix.
