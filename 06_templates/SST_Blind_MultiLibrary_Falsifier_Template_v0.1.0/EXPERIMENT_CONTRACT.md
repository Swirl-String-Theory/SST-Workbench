# Experiment contract — required per falsifier instance

The shared core is infrastructure. A scientific instance is incomplete until all six contracts below are explicit and preregistered.

| Contract | Required content | Failure semantics |
|---|---|---|
| Source | admissible libraries, hashes, provenance-family definition, parser/translator status | missing/ambiguous -> `UNRESOLVED` |
| Admissibility | geometry/topology/numerical gates before outcome scoring | prerequisite failure cannot support hypothesis |
| Discovery | target-free statistic, null, search domain, stopping rule, multiplicity correction | well-powered null win -> `FAIL` |
| Confirmation | held-out or independent source/experiment unit; no self-confirmation | absent -> `UNRESOLVED` |
| Physical provider | versioned schema, units/dimensions, hashes, solver identity and convergence requirements | malformed/unverified -> `UNRESOLVED` |
| Reveal | private targets/mappings + SHA-256 commitment; never discovery inputs | commitment mismatch -> hard stop |

## Fixed execution policy

`provenance -> admissibility -> target-free discovery -> independent confirmation -> numerical certification -> cross-source replication -> mechanism -> reveal`

The exact gate numbering may vary, but dependencies and allowed conclusions must be frozen before scientific campaign values are inspected.

## Independence rule

Declare the independent unit explicitly. Replicas generated by mesh refinement, parameter variants, repeated seeds, GPU reruns, or multiple encodings of one source do **not** automatically increase statistical sample size.

## Accelerator rule

A GPU backend may accelerate a preregistered screening observable only after CPU↔GPU parity. The CPU reference remains authoritative unless a future protocol explicitly establishes another certified backend. Accelerator disagreement is a numerical failure, not physical evidence.
